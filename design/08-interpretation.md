# 8. 表示のときの解釈

対象の版: 0.186.0

受け取ったイベントを、どう読んで画面に出すかを書きます。どこから読むかは [5 章](05-reading.md) にあります。

## 8.1 削除の依頼（NIP-09）

- 削除の依頼として扱うのは、**投稿の作者本人**の kind 5 で、`["e", <その投稿の ID>]` があるものだけです。ほかの人の kind 5 は無視します。
- 削除が依頼された投稿の ID は、アカウントごとに端末に覚えます（新しい 2,000 件）。
- リレーがまだ返してくる投稿は、隠さずに「削除が依頼された投稿です（リレーに残っています）」とたたんで出し、「表示する」で中身を見られます。消えたことに気づけるようにするためです。
- 自分の投稿なら「削除を再送」を出します（6.6）。
- 自分で削除して受理されたものは、その場で一覧とキャッシュから外します。
- 引用カードの中の投稿も、作者本人の kind 5 があれば削除された投稿として扱います。
- リアクション・リポストは、本人の kind 5 で取り消されたものを数えません（5.2）。通知には、取り消されたリアクションが残ることがあります（11 章）。

## 8.2 期限（NIP-40）

`expiration` の時刻を過ぎたイベントは、リレーから届いたときと、端末に保存した分を出すときの両方で捨てます。ステータス（NIP-38）の `expiration` も同じです。

## 8.3 ミュート（NIP-51 の kind 10000）

- 公開のタグだけを読みます。`p` の人の投稿・その人がしたリポスト、`e` の投稿、`e` の投稿をルートにした返信を出しません。パブリックチャットでも、ミュートした人とメッセージを出しません。
- `content` の非公開の項目は読みません（書き換えるときはそのまま残します。7.1）。

## 8.4 注意書き（NIP-36）

`content-warning` タグがある投稿はたたんで出し、理由（200 文字まで）を見せます。理由が空なら「センシティブな内容」と出します。

## 8.5 表示できない kind（NIP-31）

本文として描く kind は 1・1111・42・30023・1068・20・21・22・34235・34236 です。それ以外の kind が、引用や通知の対象などで出てきたときは、`alt` タグの説明（500 文字まで）を出します。`alt` がなければ「このアプリでは表示できない種類の投稿です（kind N）」と出します。表示できない kind は端末に保存しません。

## 8.6 スレッド

### 親の決め方

| kind | 親 |
|---|---|
| 1（NIP-10） | `reply` の印の最後の `e`。なければ `root` の印の最初の `e`。どちらもなければ、印のない最後の `e` |
| 1111（NIP-22） | 最後の `a`、なければ最後の `e`、なければ最後の `i` |
| それ以外 | 返信として扱わない（記事や画像の投稿の `e` は、返信ではなく言及とみなす） |

### 根の決め方

kind 1111 は最初の `A`、なければ `E`、なければ `I` です。kind 1 は `root` の印の `e` です。どちらもなければ、その投稿自体が根です。

アドレスで指すイベント（kind 30000〜39999）は、ID ではなくアドレス（`<kind>:<作者>:<d>`）でつながりを見ます。記事が書き直されても、コメントが同じ記事につながるようにするためです。

返信元は 20 段まで、返信は 200 件までを、端末にある分で木の形に並べます。同じ投稿が 2 回出る循環は止めます。

## 8.7 引用

- 引用カードに出す投稿は、`q` タグの投稿と、本文にある `nostr:note1…`・`nostr:nevent1…` の投稿です（本文のどこにあってもよい）。`q` タグを先に、本文は書かれた順に、同じ投稿を除いて 1 つの投稿につき 3 件までカードにします。4 件目からはリンクのままです。
- カードに出した投稿へのリンクは、本文のどこにあっても取り除きます。リンクだけの行は行ごと消し、行の途中のリンクは前の空白 1 つと一緒に消します。カードが 2 回出ないようにするためです。
- カードの中の投稿は、ID だけで（kind を指定せずに）取得します。nevent や `q` タグにリレーのヒントや作者があれば、読み込みリレーで見つからないときにそこからも探します。
- 本文の `nostr:npub1…`・`nostr:nprofile1…` は「@名前」で出します。名前がまだわからないあいだは、npub の先頭を短くした「@npub1…」を出し、その人のプロフィールを読みます。投稿・記事へのリンクは短く縮めて出します。

## 8.8 リポスト

- 一覧では、リポストした人と時刻の下に元の投稿を出します。並びはリポストした時刻です。
- プロフィールの投稿タブでは、リポストはリポストした人の活動として扱います（5.5）。
- 元の投稿を見つけられなかったリポストは出しません（5.2）。

## 8.9 記事（NIP-23）

- 同じアドレスの記事は、`created_at` がいちばん新しいもの（同じなら ID が小さいもの）だけを出します。
- 題名は `title`（300 文字まで）、概要は `summary`（600 文字まで、なければ本文の頭）、見出し画像は `https://` の `image` だけです。
- 本文は CommonMark と GFM（表・取り消し線・自動リンク）で読みます。HTML はタグを取り除いて文字だけを出します（`<br>` は改行にします）。投稿へのリンクだけの行は、引用カードとして埋め込みます。
- 本文の中の `nostr:npub…` は、0.186.0 では名前ではなく切り詰めた文字列で出ます（11 章）。

## 8.10 投票（NIP-88）

- `option` が 2 つ以上ある kind 1068 だけを投票として出します。選択肢は 50 個、それぞれ 200 文字までです。
- 1 人 1 票です。締め切り（`endsAt`）より前の、その人のいちばん新しい kind 1018 だけを数えます。
- 単一選択（`polltype` が `multiplechoice` でないもの）は、答えの最初の `response` だけを数えます。複数選択は、選んだ選択肢をそれぞれ 1 回数えます。

## 8.11 バッジ（NIP-58）

プロフィールに出すのは、次をすべて満たすバッジだけです。

- 相手のプロフィールのバッジ一覧（kind 10008、または `d` が `profile_badges` の kind 30008）で、`a` と `e` が続けて並んでいる
- 授与（kind 8）の作者が、定義のアドレスの作者と同じ
- 授与に、その定義の `a` と相手の `p` がある
- 定義（kind 30009）が見つかった

画像は `https://` だけを使い、小さな画像（`thumb`）は 64px 以上でいちばん小さいものを選びます。

## 8.12 ステータス（NIP-38）

`d` が `general` と `music` のものだけを、それぞれいちばん新しい 1 つ出します。`content` が空なら出しません。`r` のリンクは `https://` だけです。

## 8.13 zap（NIP-57）

- zap した人は、zap レシートの `description` に入った zap リクエストの作者です。なければ `P` タグです。
- 金額は `bolt11` の請求書の金額を使い、読めなければ zap リクエストの `amount` を使います。
- レシートを発行した LNURL サーバーの公開鍵が、相手の `lud16` の `nostrPubkey` と一致するかは確かめていません（11 章）。

## 8.14 プロフィールとメディア

- プロフィール（kind 0）は、`created_at` がいちばん新しいもの（同じなら ID が小さいもの）だけを使います。古い版が後から届いても置き換えません。
- 名前は `display_name`、なければ `name` です（160 文字まで）。アイコンは `https://` の `picture` だけを読み込みます。読み込めない人には、公開鍵から決まる生成アバターを出します（9 章）。
- NIP-05 は、プロフィールの「確認」を押したときに `https://<ドメイン>/.well-known/nostr.json?name=<名前>` を読んで確かめます（10.5）。自動では確かめません。
- 本文の画像・動画は `https://` の URL だけを読み取り、1 つの投稿で 20 件までです。一覧のカードには 4 枚と「+N」、ビューアでは全部出します。`imeta` タグ（NIP-92）の URL も使います。
- カスタム絵文字（NIP-30）は、名前が英数字・`_`・`-` の 64 文字まで、URL が 2,048 文字までの `emoji` タグだけを使います。

## 8.15 そのほかのタグ

- **件名（NIP-14）**: `subject` を本文の上に出します（120 文字まで）。本文が件名で始まるときは出しません。
- **橋渡し元（NIP-48）**: `proxy` があれば、出どころ（ActivityPub・Bluesky・RSS・Web）と、元の投稿へのリンクを出します。リンクは `https://` だけで、Bluesky の `at://` は bsky.app の URL に直します。
- **クライアントタグ**: 投稿元のアプリの名前を、名前と時刻の行に出します（6.1）。

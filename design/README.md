# ぺにょったー 技術資料

Android 向け Nostr クライアント「ぺにょったー」が、Nostr の仕様をどう使っているかを書いた文書です。使い方の説明ではありません。NIP を読んだことがある人に向けて、「どの NIP を選び、どう解釈し、仕様にないところをどう決めたか」を書きます。NIP そのものの説明はしません。

- 対象の版: **0.186.0**（2026-10-19 時点）。版が上がると内容が変わることがあります。
- 書いてあるのは、作者がソースを読んで確かめた今の動きです。リリースノートの寄せ集めではありません。ソースは公開していないので、ソースのファイル名などは書いていません。
- 「上限」「打ち切り」などの数値は今の実装の値です。変わることがあり、約束ではありません。
- 実機で確かめていない動きには「未確認」と書きます。

## 1. 用語

アプリの画面での呼び名と、NIP での呼び名の対応です。

| この文書での呼び名 | 意味 |
|---|---|
| 読み込みリレー | 自分の設定で「読む」にしたリレー。NIP-65 の `read` に当たる |
| 書き込みリレー | 自分の設定で「書く」にしたリレー。NIP-65 の `write` に当たる |
| 常時接続リレー | 読み込みリレーの先頭から N 件（既定 6 件、1〜12 件）。購読し続ける先 |
| 検索リレー | NIP-50 の検索を頼むリレー。端末内だけの設定で、NIP-65 には載せない |
| グローバルのリレー | グローバルのタイムラインを読むリレー。端末内だけの設定。空なら読み込みリレーを使う |
| DM 受信リレー | 自分の kind 10050 に載せたリレー |
| 相手の書き込みリレー | 相手の kind 10002 の `write`（アウトボックス） |
| 相手の読み込みリレー | 相手の kind 10002 の `read`（インボックス） |
| 一回きりの取得 | REQ を送り、EOSE か打ち切りで CLOSE するもの（4.3） |
| 購読 | REQ を送ったまま、画面を閉じるまで受け取り続けるもの |
| 受理 | リレーが `OK` で `true` を返したこと |

イベントの種類は「kind 1」のように番号で書きます。タグは `["e", <ID>]` のように JSON で書きます。

# 5. 読み込み

対象の版: 0.186.0

画面ごとに、どの REQ を、どのリレーへ送るかを書きます。「相手の書き込みリレーから」と書いたものは、[4.4](04-relays.md#44-相手のリレーアウトボックス) の方法で読みます。一人分なら 4.4.2、何人分なら 4.4.3 です。どちらも、自分の読み込みリレー（または常時接続リレー）を少し遅れて足します。

フィルタは JSON で書きます。`<自分>` は自分の公開鍵です。

## 5.1 共通の決まり

- **同じものが何度届いてもよい。** イベントは ID で 1 つにまとめます。
- **置き換え可能なイベントは、いちばん新しいものだけを使う。** `created_at` が大きいもの、同じなら ID が小さいものです（NIP-01）。
- **ミュートは読むときに除く。** kind 10000 の `p` の人の投稿、その人がしたリポスト、`e` の投稿、`e` の投稿をルートにした返信は表示しません。REQ では除きません。
- **端末に保存したものを先に出す。** ホーム・通知・スレッドは、前回保存した分をすぐに出してから、リレーに取りに行きます。保存しない kind（表示できないもの）もあります。
- **削除の依頼（kind 5）は隠さずにたたむ。** 8 章で書きます。
- **期限（NIP-40）を過ぎたものは捨てる。** 届いたときと、端末の保存分を出すときの両方で確かめます。

## 5.2 ホーム

### フォロー中

```json
{"kinds": [1, 6, 16, 30023, 1068, 20, 21, 22, 34235, 34236], "authors": [<フォロー中>, <自分>], "limit": 80}
```

- 相手の書き込みリレーへ購読し、常時接続リレーへも全員分を購読します（4.4.3）。フォローは全員を相手のリレーに振り分けます（0.188.0 までは 500 人まで）。自分の書き込みリレーには、振り分けの 12 件に入らなくても必ず問い合わせます（0.186.0 の次の版から）。
- 「更新」と「さらに読む」は同じフィルタの一回きりの取得です（さかのぼり方は 4.3.1）。
- フォロー一覧は、端末に保存した自分の kind 3 です。自分の kind 3 は常時接続リレーで購読し続け、新しいものが届いたら取り込みます（大きく減ったときの扱いは 7 章）。

### グローバル

フォロー中と同じフィルタから `authors` を外したものを、グローバルのリレーへ送ります。購読は「グローバルのリレー」（空なら常時接続リレー）、「さらに読む」は「グローバルのリレー」（空なら読み込みリレー全部）です。

### 届いたものの扱い

- 購読で届いたイベントは 0.12 秒ためて（最大 200 件）、まとめて一覧に入れます。
- 一覧に出るのは kind 1・30023・1068 と、リポスト（kind 6・16）です。リポストは、元の投稿が kind 1・1111 のときだけ出します。
- 画像・動画の投稿（kind 20・21・22・34235・34236）も一覧に出ます。0.186.0 までは、REQ には入っていたのに一覧を作るときに捨てていて、ホームにもプロフィールの投稿タブにも出ませんでした（不具合）。0.186.0 の次の版から出ます。
- kind 30023 は、同じ記事（作者と `d`）の新しい版が届いたら、古い版を一覧から外します。

### リポスト元の探し方

kind 6・16 の元の投稿は、次の順に探します。見つからなかったリポストは表示しません。

1. リポストの `content` に入っている署名つきのイベント。署名を確かめ、kind 1・1111 のときだけ使います。
2. すでに一覧や端末にある投稿。
3. 読み込みリレーへ `{"kinds": [1, 1111], "ids": [...]}`。
4. まだ見つからない分は、次の 2 つを同時に問い合わせます。
   - リポストの `e` タグのリレーヒント。多く書かれていたものから 4 件まで。読み込みリレーに含まれるもの、`wss://` 以外、IP アドレス、`localhost`、`.local`・`.localhost`、ドットのない名前は使いません。
   - リポストの `p` タグの人（1 つのリポストにつき 3 人まで、合わせて 20 人まで）の書き込みリレー。

### 一緒に読むもの

一覧に出た投稿について、次も読みます。

| 何を | フィルタ | どこから |
|---|---|---|
| プロフィール | `{"kinds": [0], "authors": [...]}`（80 人ずつ） | 相手の書き込みリレー |
| ステータス（NIP-38） | `{"kinds": [30315], "authors": [...]}` | 相手の書き込みリレー |
| Blossom のサーバー一覧 | `{"kinds": [10063], "authors": [...]}` | 相手の書き込みリレー |
| 反応と削除の依頼 | `{"kinds": [1, 5, 6, 7, 16, 1111], "#e": [<新しい 100 件の ID>], "limit": 1000}` | 読み込みリレー |
| 反応の取り消し | `{"kinds": [5], "#e": [<上で届いた kind 6・7・16 の ID>]}` | 読み込みリレー |

プロフィールを読む相手は、投稿の作者、リポストした人、本文の `nostr:npub…`・`nostr:nprofile…` の人です。端末に保存したプロフィールがあれば先に出し、リレーの返事は届いたものから順に反映します。ステータスと Blossom のサーバー一覧は、名前の読み込みを待たせないよう、別の順番で読みます。ほかの画面（通知・検索・プロフィール・リスト・チャット）でも、本文に名前のわからない人がいれば同じように読みます。どの画面で読んだプロフィールも、より新しい版ならホームの表示にも使います。

返信・リポスト・リアクションの数は、上の 2 つから数えます。返信は、NIP-10・NIP-22 の親がその投稿のものだけを数えます。zap の数は数えません。本人が kind 5 で取り消したリアクション・リポストは数えません。投稿の作者本人の kind 5 が届いたら、その投稿を「削除が依頼された投稿」として扱います（8 章）。

## 5.3 通知

```json
{"kinds": [1, 6, 7, 8, 16, 1111, 9735], "#p": [<自分>], "until": ..., "limit": 100}
```

- 読み込みリレーへの一回きりの取得と、フォロー中の人の書き込みリレーへの取得（4.4.3 の方法。ただし常時接続リレーは足さない）を同時に行います。フォロー中の人からの反応が、その人のリレーにしかない場合に拾うためです。
- 取得全体は 40 秒で打ち切り、取れた分を出します。前の取得が 45 秒を超えて残っていたら、「再取得」を押したときにやめてやり直します。
- アプリを開いている間は、読み込みリレーで同じフィルタ（`since` は 30 秒前）を購読し続けます。届いたものは 0.4 秒ためてから一覧とタブの印に入れます。アプリが裏に回ったら購読をやめ、戻ったら 30 秒前から購読し直します。プッシュ通知はありません。
- 一覧に残すのは新しい 500 件までです。

### 通知として出すもの

次をすべて満たすものだけを出します。

- 作者が自分ではない
- `["p", <自分>]` がある
- kind 9735 は、中の zap リクエスト（`description`）の作者が自分ではない（zap した人として、その作者を出す）
- 何についての通知かが決まる（下の表）

| kind | 何についての通知か |
|---|---|
| 1（`q` タグか本文末尾の `nostr:note`・`nevent` がある） | 引用した投稿 |
| 1 | NIP-10 の返信先 |
| 1111 | `q` タグ、なければ最後の `e`、なければ NIP-22 の親 |
| 6・7・16・9735 | 最後の `e` |

zap レシートを発行した LNURL サーバーの公開鍵は確かめていません（11 章）。

### 対象の投稿

対象の投稿は `{"ids": [...]}`（kind を指定しない）で、自分の書き込みリレーと読み込みリレーから読みます。リアクションはパブリックチャットのメッセージ（kind 42）などにも付くので、kind を絞りません。kind 0・3・5 は対象として使いません。

対象が自分のリアクション（kind 7）のときは「あなたのリアクションへのリアクション」として、そのリアクションの最後の `e` の投稿も、最後の `p` の人の書き込みリレーから読みます。

## 5.4 投稿の詳細（スレッド）

選んだ投稿について、次を同時に読みます。送り先は読み込みリレーです。「作者の」と書いたものは、作者の書き込みリレーも使います。

| 何を | フィルタ | どこから |
|---|---|---|
| 選んだ投稿（どのリレーにあるか） | `{"kinds": [<kind>, 6], "ids": [<ID>]}` | 作者の |
| 返信元をたどる | `{"kinds": [1, 1111], "ids": [<親>]}`。親がアドレスなら `{"kinds": [<kind>], "authors": [<作者>], "#a": [<アドレス>]}` | 読み込みリレー |
| 返信 | `{"kinds": [1, 1111], "#e": [<ID>]}`。アドレスで指すイベントなら `#e` の代わりに `#a` | 読み込みリレー |
| 返信の返信 | `{"kinds": [1, 1111], "#e": [<返信の ID>...]}` | 読み込みリレー |
| リポストとリアクション | `{"kinds": [6, 7, 16], "#e": [<ID>], "limit": 500}` | 読み込みリレー |
| その取り消し | `{"kinds": [5], "#e": [...]}` | 読み込みリレー |
| リアクションへのリアクション | `{"kinds": [7], "#e": [<リアクションの ID>...]}` と、その取り消し | 読み込みリレー |
| プロフィール | `{"kinds": [0], "authors": [...]}` | 作者の |

- 返信元は 20 段までたどり、全体で 20 秒かけても届かなければ「返信元の一部を取得できませんでした」と出します。
- 返信は、開いている間 `since` を 5 秒前にして購読し続けます。
- 親と根の決め方は、kind 1 は NIP-10（`root`・`reply` の印、印がなければ位置）、kind 1111 は NIP-22 です。NIP-22 では、親・根ともにアドレスのタグ（`a`・`A`）を ID のタグ（`e`・`E`）より優先します。

## 5.5 プロフィール

相手の書き込みリレー（一人分、4.4.2）から読みます。

| 何を | フィルタ |
|---|---|
| プロフィール | `{"kinds": [0], "authors": [<相手>], "limit": 1}` |
| 投稿 | `{"kinds": [1, 6, 16, 1111, 1068, 20, 21, 22, 34235, 34236], "authors": [<相手>]}`（さかのぼり方は 4.3.1、1,000 件まで） |
| ピン留め（NIP-51） | `{"kinds": [10001], "authors": [<相手>]}`。中の投稿は読み込みリレーから `{"kinds": [1], "ids": [...]}` |
| ステータス | `{"kinds": [30315], "authors": [<相手>]}` |
| フォロー | `{"kinds": [3], "authors": [<相手>], "limit": 5}` |
| フォロワー数 | 読み込みリレーへ `COUNT` `{"kinds": [3], "#p": [<相手>]}`（4.6） |
| バッジ（NIP-58） | `{"kinds": [10008, 30008], "authors": [<相手>]}`。授与（kind 8）は読み込みリレー、定義（kind 30009）は授与した人の書き込みリレー |
| 記事 | `{"kinds": [30023], "authors": [<相手>], "limit": 100}` |
| リアクション | `{"kinds": [7], "authors": [<相手>], "limit": 100}`。リアクション先は読み込みリレーから `{"kinds": [1, 1111], "ids": [...]}` |
| リレー | 相手の kind 10002（4.4.1 と同じもの） |

投稿タブのリポストは、リポストした人の活動として扱います。相手がしたリポストは相手のプロフィールに出て、相手の投稿がほかの人にリポストされたものは出しません。

### フォロワーの一覧

フォロワーの一覧は、開いたときだけ作ります。

1. 読み込みリレーから `{"kinds": [3], "#p": [<相手>], "limit": 500}` を読み、作者を 500 人まで集めます。
2. その人たちの最新の kind 3 を、それぞれの書き込みリレーから読み直します（4.4.3）。
3. 最新の kind 3 に今も相手が入っている人だけをフォロワーとします。古い kind 3 だけが残っているリレーがあっても、外したフォローを数えないためです。

数は `COUNT`、一覧はこの方法なので、2 つが合わないことがあります。

## 5.6 検索

まず端末に保存した投稿とプロフィールから探して出し、そのあとリレーに問い合わせます。リレーは同時に 4 つまでです。

| 入力 | フィルタ | どこへ |
|---|---|---|
| 文字 | `{"kinds": [...], "search": "<文字>"}` と `{"kinds": [0], "search": "<文字>", "limit": 50}` | 検索リレーのうち、NIP-11 で NIP-50 対応と分かったもの全部と、分からないもの 2 件 |
| `#タグ` | `{"kinds": [...], "#t": ["<タグ>"]}` | 検索リレーと読み込みリレー |
| npub・nprofile・NIP-05 | `{"kinds": [0], "authors": [<相手>]}` と `{"kinds": [...], "authors": [<相手>]}` | ヒント、相手の書き込みリレー、そのあと検索リレーと読み込みリレー |
| note・nevent | `{"ids": [<ID>], "limit": 1}`（kind を指定しない） | 同上 |
| naddr | `{"kinds": [<kind>], "authors": [<作者>]}` | 同上 |
| 作者で絞り込み | `{"kinds": [...], "authors": [...]}` | 作者（20 人まで）の書き込みリレー、そのあと読み込みリレーと検索リレー |

- 文字の検索は、NIP-50 に対応した検索リレーがなければリレーに送りません。
- 「そのあと」と書いたリレーへは 0.7 秒遅れて送ります。
- リレーごとに進み具合を出し、失敗したときは NIP-11 の情報で「有料」「認証が必要」を見分けて出します。
- 表の `"kinds": [...]` は 1・1111・30023 です。「コメント」に絞ると 1111 だけです。

## 5.7 DM

DM は、署名できるアカウントでだけ読みます。閲覧専用のアカウントでは取得もしません。

| 何を | フィルタ | どこから |
|---|---|---|
| NIP-17 | `{"kinds": [1059], "#p": [<自分>], "since": ..., "limit": 200}` | 自分の kind 10050 のリレーと読み込みリレー |
| NIP-04（受け取った分） | `{"kinds": [4], "#p": [<自分>], ...}` | 読み込みリレー |
| NIP-04（送った分） | `{"kinds": [4], "authors": [<自分>], ...}` | 読み込みリレー |

- 自分の kind 10050 は、読み込みリレーと書き込みリレーから探し、10 分覚えておきます。このアプリで公開し直したら捨てます。
- gift wrap（kind 1059）を開き、seal（kind 13）の署名と、seal の作者と rumor の作者が同じことを確かめます。rumor は kind 14・15 だけを使い、ID を計算し直して確かめます。
- 受信リレーが AUTH を求め、署名アプリが画面を出さずに答えられないときは、そのリレーの分は読めません（4.2.2）。
- 一覧を作るときの復号は、署名アプリの画面を出さずに頼みます。断られた分は出しません。

| チャンネルの情報の更新 | `{"kinds": [41], "#e": [<チャンネル>...]}`。作成者のものだけ使う | 読み込みリレー |

## 5.9 リスト（NIP-51 のフォローセット）

- 自分の kind 30000 を、自分の書き込みリレーと読み込みリレーから読みます。`d` が `mute` のものは出しません。
- 署名できるアカウントでは、`content` の非公開メンバーを復号します（NIP-44、だめなら NIP-04）。復号のために署名アプリの画面を出すことがあります。
- リストのタイムラインは `{"kinds": [1, 6, 16], "authors": [<メンバー>], "limit": 80}` を、メンバーの書き込みリレーから読みます（4.4.3）。

## 5.11 前後の投稿

投稿の「この時点のタイムライン」と、リポストの「リポストした人のその後」で開きます（0.191.0 の次の版から）。選んだ投稿（またはリポスト）を真ん中に、上にそのあと、下にその前を並べます。範囲は、フォロー中（5.2 と同じ読み方）・グローバル（「グローバルで読むリレー」）・その人だけ（その人の書き込みリレー）から選べます。リポストから開いたときは、リポストした人だけで開きます。

- 前: `{"kinds": [1, 6, 16], "until": <いちばん古い時刻>, "limit": 30}` を繰り返します（その人だけのときは 1111 も）。
- 後: リレーは条件に合うものを新しい順に返すので、`since` だけでは直後ではなく最近のものが返ります。そこで `{"since": <時刻>, "until": <時刻 + 1 時間>, "limit": 500}` の区切りごとに読み、古いほうから 30 件を使います。見つからなければ区切りを 4 倍ずつ広げ（約 1 か月まで）、今を越えたら終わりです。

日時を指定して開くこともできます（「その他」の「日時を指定して見る」）。このときは真ん中に投稿を置かず、その時刻に「この時刻」の線を引き、上にそれ以降、下にそれより前を並べます。

## 5.12 引用した投稿・2 人の会話・投稿カレンダー

- 引用した投稿: 投稿詳細で、その投稿を引用した投稿を `{"kinds": [1, 1111], "#q": [<ID>], "limit": 200}` で読み取りリレーから探し、「引用した投稿（件数）」の下にたたんで出します。本文の `nostr:` リンクだけで引用し、`q` タグを付けていない投稿は見つかりません。
- 2 人の会話: 返信の「この 2 人の会話」で開きます。返信した人 A と、返信先の人 B（`p` タグの最初の、A 以外の人）について、A が書いて `p` に B を含む投稿と、B が書いて `p` に A を含む投稿を、それぞれの書き込みリレーから `{"kinds": [1, 1111], "authors": [A], "#p": [B], "limit": 40}` のように読み、古い順に並べます。ほかの人の発言は入りません。
- 投稿カレンダー: プロフィールの「投稿カレンダー」で、直近 12 週の日ごとの投稿数を濃さで出します。その人の書き込みリレーから 500 件ずつ 6 回までさかのぼって数え、読みきれなかったときは、それより前の日を「未取得」として出します。日の区切りは端末のタイムゾーンです。日を押すと、その日の 0 時を指定した「その人だけ」の前後の投稿（5.11）を開きます。

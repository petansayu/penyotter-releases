# 11. 対応していないこと・既知の制限

対象の版: 0.186.0

## 11.1 対応していないこと

| 内容 | 補足 |
|---|---|
| `nostrconnect://`（NIP-46） | `bunker://` だけに対応（3.4） |
| NIP-46 の `connect` でのアプリ情報 | 名前などを渡していない |
| プッシュ通知・裏での受信 | アプリを開いている間だけ通知を受け取る（5.3） |
| ミュート一覧の非公開の項目 | 読まない。書き換えるときは `content` をそのまま残す（8.3） |
| zap レシートの発行者の確かめ | LNURL サーバーの公開鍵と `nostrPubkey` を比べていない（8.13） |
| アドレスで指すイベントへのリアクション・リポスト・zap の `a` タグ | `e` だけを付けている |
| 引用の `nevent` | 引用で本文に足すのは `nostr:note1…`（6.5）。`q` タグは付けている |
| チャンネルの情報の更新（kind 41） | 読むだけで、作らない |
| 投票の作成（kind 1068） | 表示と投票だけ |
| 非公開のリレー一覧（kind 10013） | 読むだけで、作らない（6.10） |
| リレーの下書き（NIP-37）を読み戻す画面 | 保存と削除だけ |
| 読み込みのときに相手の読み込みリレーを使うこと | ゆるアウトボックスは送信だけ（6.1） |
| 端末の外への暗号化バックアップ | 設計中（7.5） |
| AT Protocol（Bluesky）との直接の連携 | 見送った。NIP-48 の橋渡し元の表示だけ（8.16） |

NIP-04（DM）・NIP-28（パブリックチャット）・NIP-96（ファイル保存）は、仕様では「推奨しない」とされていますが、使っている人がいるので対応を続けています。

## 11.3 仕組みからくる制限

- **AUTH**: 署名アプリ（NIP-55）で AUTH を「常に許可」にしていないと、認証が必要なリレーから読めない分があります（4.2.2）。NIP-17 の DM の受信リレーに多いので、DM が読めないことがあります。
- **アウトボックス**: フォロー中の人のリレーへ一度に問い合わせるのは 12 件までです。ほかのリレーにだけ書いている人の投稿は、常時接続リレーにあるときだけ読めます（4.4.3）。
- **フォロワー**: 数（`COUNT`）と一覧（kind 3 から作る）は方法が違うので、合わないことがあります。一覧は 500 人までです（5.5）。
- **通知**: 残すのは新しい 500 件までです（5.3）。
- **キャッシュ**: タイムラインは一覧ごとに既定 2,000 件までで、古いものから消します（2.3）。
- **時刻**: 端末の時刻より 10 分以上先の `created_at` のイベントは捨てます（4.2.1）。

## 11.4 実機で確かめていないこと

次の動きは、コードとテストでは確かめましたが、実際のリレーに送って確かめてはいません。

- 消去の依頼（NIP-62）、投票（NIP-88）、記事（NIP-23）の公開
- パブリックチャットのメニューからのリアクション・返信・引用・通報、チャンネルの作成
- NIP-55・NIP-46 のアカウントでのリアクション・リポスト・DM の送受信
- AUTH を求めるリレーでの NIP-17 の DM の受け渡し
- 画像の変換でメタデータ（Exif など）が消えるか

# 10. 外部への通信とプライバシー

対象の版: 0.201.0

アプリがどこに、何を送るかをまとめます。このアプリには運営者のサーバーがなく、利用状況の収集（アクセス解析・クラッシュレポートなど）もしていません。通信先は、リレーと、投稿・プロフィールに書かれた URL のサーバー、利用者が選んだサーバーだけです。

暗号化されていない HTTP と `ws://` では通信しません。

## 10.1 一覧

| 通信先 | いつ | 相手に分かること | 切り替え |
|---|---|---|---|
| リレー（WebSocket） | 常に | IP アドレス、読んでいるもの（フィルタ）、送ったイベント。AUTH に答えたリレーには公開鍵 | リレーの設定 |
| 画像・動画のサーバー | 画像・アイコン・動画を表示したとき | IP アドレス、その画像を見たこと | 設定「見た目」で画像・動画・アイコン画像の読み込みを切れる |
| リンク先のサイト | リンクプレビューを出すとき | IP アドレス、そのページを開いたこと | 設定「見た目」の「リンクプレビューを表示」 |
| NIP-05 のドメイン | プロフィールの「確認」を押したとき、検索や閲覧専用のアカウントの追加で `名前@ドメイン` を入れたとき | IP アドレス、問い合わせた名前 | なし |
| リレーの NIP-11 | 検索の前、リレーの情報画面 | IP アドレス | なし |
| 画像のアップロード先 | 画像・動画を添付したとき、DM でファイルを送るとき | IP アドレス、ファイル、署名した認証イベント（公開鍵） | 設定でアップロード先を選ぶ |
| LNURL のサーバー | zap するとき | IP アドレス、署名した zap リクエスト（6.11） | なし（zap しなければ通信しない） |
| 自分の Lightning アドレスのサーバー | プロフィールに設定しているとき、開いて最初の通知の取得で 1 回 | IP アドレス（zap レシートの発行者を確かめるため。8.13） | なし（設定していなければ通信しない） |
| GitHub（`api.github.com`） | 1 日 1 回、アプリを開いたとき（配布している版だけ）と、「このアプリについて」の「更新を確かめる」を押したとき | IP アドレス、アプリの版（`User-Agent`） | 「このアプリについて」の「1 日 1 回、更新を確かめる」 |
| Hugging Face（`huggingface.co` と、そこから移されるファイルの置き場） | 「その他」→「翻訳」で、ライセンスに同意して翻訳のモデルをダウンロードするとき | IP アドレス、アプリの版（`User-Agent`） | なし（ダウンロードしなければ通信しない） |
| GitHub（`github.com` と、そこから移されるファイルの置き場） | 新しい版の「更新する」を押したとき | IP アドレス、アプリの版（`User-Agent`） | なし（押さなければ通信しない） |
| Lightning ウォレット | zap の請求書を払うとき | 端末のウォレットアプリに `lightning:` で渡す | なし |

## 10.2 リレー

- 1 つのリレーにつき接続は 1 本です（4.2）。読み込みリレー・書き込みリレーのほか、ほかの人の投稿を読むときは、その人の kind 10002 の書き込みリレーにもつなぎます（4.4）。つまり、**自分が設定していないリレーにもつなぎます**。フォロー中の人が多いと、つなぐリレーも増えます（一度に問い合わせるのは 12 件まで）。
- ほかの人のリレーリストやリポストのヒントに書かれたアドレスのうち、`localhost`、プライベートな IP アドレス（`10.`・`192.168.`・`172.16〜31.`・`127.`）、IP アドレスそのもの、`.local` などは使いません。自分の家のネットワークの機器へつながされるのを防ぐためです。
- AUTH（NIP-42）に答えると、そのリレーに自分の公開鍵が分かります。答えるのは自分で選んだリレーと、送信中のリレーだけです。閲覧専用のアカウントは答えません（4.2.2）。

## 10.3 画像・動画

- 画像の読み込みには `User-Agent: PestrReader/<版> Android`（アプリの旧名）を送ります。動画の最初のコマを読むときも同じです。
- 画像はリダイレクトをたどります。キャッシュは端末に既定 64MB です（2.3）。
- アイコン画像を読み込まない設定にすると、全員が生成アバター（9.2）になり、アイコンのための通信をしません（ほかの人のプロフィール画面の大きなアイコンと、プロフィール編集のプレビューだけは画像を読みます）。

## 10.4 リンクプレビュー

- 本文の `https://` のリンク先のページを読み、`og:title`・`og:description`・`og:image`（なければ `twitter:` や `<title>`）を出します。
- 送る `User-Agent` はブラウザに似せたものに `PestrReader` を足したものです。ブラウザ向けの OGP しか返さないサイトがあるためです。
- リンク先は `https://`（ポート 443）だけです。名前を引いた先にプライベートな IP アドレス（NIP-05 と同じ範囲。10.5）が含まれていたら読みません。この確かめは実際につなぐときの名前の引き直しにもかけるので、確かめたあとで名前の向き先を家のネットワークに変えられても、つながりません。リダイレクトは 6 回まで、そのたびに同じ確かめをします。
- 読むのは HTML の頭から 768KB までです。同時に 3 件までで、失敗した URL は 5 分間読み直しません。
- プレビューの画像は `https://` で、ポートが 443 のものだけです。

## 10.5 NIP-05

- `https://<ドメイン>/.well-known/nostr.json?name=<名前>` を読みます。リダイレクトはたどりません。
- 名前は小文字の英数字と `_`・`.`・`-`、ドメインは国際化ドメインを ASCII にしたもので、`.local`・`.localhost` は使いません。
- 名前を引いた先にプライベートな IP アドレス（ループバック、リンクローカル、サイトローカル、マルチキャスト、CGNAT の `100.64/10`、`198.18/15`、IPv6 のユニークローカルなど）が含まれていたら、つなぎません。
- 応答は 256KB まで、接続から 10 秒で打ち切ります。

## 10.6 NIP-11

- リレーの URL を `https://` に置き換えて、`Accept: application/nostr+json` で読みます。`User-Agent` は `PestrReader RelayInfo` です。
- 応答は 128KB まで、4 秒で打ち切ります。結果は 1 日覚えます。
- 検索で NIP-50 に対応しているか、有料か、認証が必要かを見分けるのに使います（5.6）。リレーの情報画面のリンクは `https://` だけを出します。

## 10.7 画像のアップロード

アップロード先は、Blossom か NIP-96 のサーバーを設定で選びます。最初の候補は blossom.band です。DM のファイルは、選んだ先に送れなければ blossom.band に送ります。

| 方式 | 認証 |
|---|---|
| Blossom | kind 24242（`["t", "upload"]`、5 分後の `expiration`、`["x", <SHA-256>]`、`["server", <ホスト>]`、`content` は `Upload image`）を `Authorization: Nostr <base64>`（標準の base64、パディングあり。URL 用の base64 を受け付けないサーバーがあるため）で送る |
| NIP-96 | NIP-98 の kind 27235（`["u", <API の URL>]`、`["method", "POST"]`、`["payload", <SHA-256>]`）を `Authorization: Nostr <base64>` で送る |

- 認証イベントはリレーには送りません。ただし、アップロード先のサーバーには自分の公開鍵と署名が渡ります。
- アップロードできる大きさは 25MB までです。0.186.0 までは、画像が大きすぎるときの案内が誤って「10MB 以下」と出ていました。0.187.0 から、実際の上限を出します。
- 画像の Exif などのメタデータが変換で消えるかは、確かめていません（未確認）。
- 返ってきた URL は、送ったファイルの SHA-256 と同じハッシュのときだけ使います。blossom.band のように画像を変換して別のハッシュで返すサーバーは、同じサーバー（サブドメインを含む）の URL にそのハッシュが入っているときだけ受け付けます。

## 10.8 更新の確認

- 配布ページ（GitHub の penyotter-releases）の最新のリリースを `https://api.github.com/repos/petansayu/penyotter-releases/releases/latest` で読み、版の番号（`tag_name`）と、リリースノートに書いた APK の SHA-256 だけを使います。リダイレクトはたどらず、応答は 256KB まで、10 秒で打ち切ります。
- 新しい版があれば知らせます。開く配布ページと、ダウンロードする APK の URL（`https://github.com/petansayu/penyotter-releases/releases/download/v<版>/Penyotter-<版>.apk`）は版の番号から組み立て、応答に書かれた URL は使いません。
- 「更新する」を押すと、APK をダウンロードし、次をすべて満たすときだけ Android のインストール画面に渡します。満たさなければ渡さずに理由を出します。
  - リリースノートに書いた SHA-256 と一致する。GitHub が応答に APK のハッシュ（`digest`）を載せているときは、それとリリースノートの値も一致する。どちらかがなければ、アプリからは更新せず配布ページを開くだけにする。
  - このアプリ（同じパッケージ名）の APK で、いまより新しい版（`versionCode`）。
  - 64MB 以下で、https のまま届いた（GitHub はファイルの置き場へ移すので、リダイレクトは https の間だけたどる）。
- 署名の鍵が違う APK は Android が上書きしません。インストールは必ず Android の画面で利用者が確かめてから行います（確認なしの自動更新はしません）。最初の 1 回は、Android の設定で、このアプリに「アプリのインストール」を許してもらいます。
- 配布している版（release 版）だけが自分を更新します。
- ダウンロードした APK はアプリのキャッシュに置き、インストール画面に渡したら消します。
- 「この版は知らせない」を選んだ版は、次の版が出るまで知らせません。

## 10.8.1 端末内の翻訳

- 翻訳は、端末の中で PLaMo 3 Translate 0.8B（株式会社 Preferred Networks、PLaMo コミュニティライセンス）を llama.cpp で動かして行います。投稿の中身はどこにも送りません。
- モデル（約 550 MB）はアプリに入っておらず、使う人がライセンスに同意してから Hugging Face から取ります。取る先は決まったリビジョンのファイルだけで、取ったあと SHA-256 を確かめてから使います。
- 元の言語の表示には、Android に入っている言語の判定を使います（端末の中で行われます）。
- 64 ビットの ARM の CPU と、3 GB 以上のメモリがある端末だけで出します。

## 10.9 端末の中で守っていること

- 秘密鍵は Android Keystore の鍵で暗号化して保存し、自動バックアップからは外しています（2.3、3.2）。
- 秘密鍵を表示する画面は撮影を禁止しています（3.2）。
- 開くときに端末の画面ロックで確かめる「アプリのロック」を選べます（3.2）。
- `nostr:nsec1…` や `nostr:ncryptsec1…` のリンクを渡されても開かず、注意を出します。秘密鍵をリンクで受け取らないためです。
- ほかのアプリからの `nostr:` リンク（NIP-21）は、npub・nprofile・note・nevent・naddr だけを開きます。

# 6. 書き込み

対象の版: 0.186.0

アプリが作るイベントを kind ごとに書きます。付けるタグ、`content` の作り方、送り先です。送信のしかた（受理の待ち方、再送）は [4.5](04-relays.md#45-送信) にあります。

## 6.1 共通の決まり

### 時刻

- 普通のイベントの `created_at` は、署名するときの端末の時刻です。
- 置き換え可能な一覧（kind 0・3・10000 番台・30000 番台の一部）は、今の時刻と、前の版の `created_at` + 1 のうち大きいほうです。端末の時計が少し遅れていても、前の版より新しくなるようにするためです。フォロー一覧とプロフィールは、前の版の時刻が今より 1 分以上先なら、書き換えをやめます。

### クライアントタグ

次の kind には、設定でオフにしていなければ（アカウントごと、最初はオン）、クライアントタグを付けます。すでに `client` タグがあれば付けません。

```json
["client", "ぺにょったー", "31990:8fc9fe720f7706a14808eed3433c91b3ea3ae4164caa6d21d94417448d0d4188:penyotter", "wss://yabu.me"]
```

対象: kind 1・6・7・16・20・21・22・42・1111

アドレスの先は、このアプリの NIP-89 のアプリ情報（kind 31990）です。ほかのアプリの投稿のクライアントタグは、名前・アドレス・リレーの形が正しいときだけ表示します。0.175.0 より前の名前（カタカナの「ペにょったー」）も、このアプリのものとして扱います。

### 署名と再送

署名したイベントは、送る前に端末の下書きに保存します。受理されなかったとき、利用者が再送すると同じイベント（同じ ID・署名）を送ります。返信先の情報が端末にない返信は、先に返信先を取り直してから署名します。

### 送り先

特に書いていないものは、**自分の書き込みリレー**へ送ります。

**ゆるアウトボックス**: ほかの人の投稿への返信・引用・リアクション・リポストは、書き込みリレーに加えて、その投稿の作者の kind 10002 の読み込みリレー（インボックス）へも 3 件まで送ります。作者の kind 10002 は 4 秒まで探し、見つからなければ書き込みリレーだけに送ります。自分の投稿への返信などには足しません。

ゆるアウトボックスは「送るときに、相手の読み込みリレーを送り先に足す」決まりで、送信だけのものです。読み込みでは、これとは別に、ほかの人の投稿を相手の書き込みリレー（アウトボックス）から読みます（[4.4](04-relays.md#44-相手のリレーアウトボックス)、[5 章](05-reading.md)）。読み込みのときに相手の読み込みリレーを使うことはありません。

## 6.3 投稿（kind 1）

`content` は入力した本文です。20,000 文字までです。添付した画像・動画の URL は、本文の後ろに改行で区切って並べます（入力欄には URL を出しません）。

付けるタグは次のとおりです。

| タグ | 付けるとき |
|---|---|
| `["t", <小文字にしたハッシュタグ>]` | 本文に `#タグ` がある。直前が文字・数字・`_`・`/` の `#` は対象外 |
| `["emoji", <名前>, <URL>]` | 本文でカスタム絵文字（NIP-30）を使った。絵文字セット（kind 30030）から使った絵文字は、4 つ目の値にそのセットの住所 `30030:<作者>:<d>` を付ける（リアクション・ステータスも同じ） |
| `["content-warning", <理由>]` | 注意書きを付けた（200 文字まで） |
| `["imeta", "url …", "m …", "x …", "size …", "dim …"]` | 本文にこのアプリでアップロードした画像の URL がある（NIP-92） |
| `["expiration", <時刻>]` | 消える投稿にした（NIP-40） |
| `["q", <ID>, <リレー>, <作者>]` と `["p", <作者>]` | 本文に `nostr:nevent…`・`nostr:note…` がある（10 件まで。作者が分かるときだけ `p`） |
| `["p", <公開鍵>]` | 本文に `nostr:npub…`・`nostr:nprofile…` がある（20 人まで、自分は除く） |

- メンションの補完で選んだ人は、本文に `nostr:npub1…` として入ります。入力欄では「@名前」と見せています。
- 画像を 1 枚アップロードするたびに、kind 1063（`url`・`m`・`x`・`size`・`dim`）も送ります。送れなくても、画像の添付は失敗にしません。
- 隠しメッセージ（9 章）は本文の一部で、タグは付けません。

### 画像・動画の投稿（kind 20・21・22・34235・34236）

投稿欄で「画像の投稿」などを選んだときは、kind 1 ではなくこれらの kind で送ります。`content` は説明文、タグは `imeta`（`url`・`m`・`x`・`dim`）と、それぞれの `m`・`x` です。kind 34235・34236 は `d`（指定がなければ 1 つ目の SHA-256）を付けます。題名があれば `title` を付けます。消える投稿にしたときは `expiration` を付けます。

## 6.4 返信

### kind 1 への返信（NIP-10）

kind 1 で、印付きの `e` タグを使います。

1. 返信先の `e` タグのうち `root` の印のもの、なければ印のない最初のものを根とします。なければ返信先そのものが根です。
2. `["e", <根>, <根のリレー>, "root", <根の作者>]` を付けます。根のリレーと作者は、返信先のタグに書かれていればそのまま使います。
3. 根と返信先が違うときは、`["e", <返信先>, "", "reply", <返信先の作者>]` も付けます。
4. 返信先の `p` タグの人と、返信先の作者を `p` で付けます。

返信先に件名（NIP-14 の `subject`）があれば、先頭に「Re: 」を付けて引き継ぎます。すでに「re:」で始まっていれば（大文字小文字を問わない）そのまま使います。

6.3 のタグ（ハッシュタグ、メンションなど）も同じように付けます。

### kind 1 以外への返信（NIP-22）

記事・画像の投稿・コメントなど、kind 1 以外への返信は kind 1111 です。

| タグ | 値 |
|---|---|
| 根 | 返信先がコメントなら、その `A`・`E`・`I` をそのまま使う。返信先がアドレスで指すイベントなら `["A", <アドレス>, ""]`。それ以外は `["E", <ID>, "", <作者>]` |
| `K` | 返信先の `K`、なければ返信先の kind |
| `P` | 返信先の `P`、なければ返信先の作者 |
| `a` | 返信先がアドレスで指すイベントのとき `["a", <アドレス>, ""]` |
| `e` | `["e", <返信先>, "", <返信先の作者>]` |
| `k` | 返信先の kind |
| `p` | 返信先の `p` の人と、返信先の作者 |

NIP-22 のとおり、公開鍵は `E`・`e` にだけ書き、`A`・`a` には書きません。アドレスで指すイベントには、`a` と `e` の両方を付けます（新しい版が出ても、どの版への返信か分かるように）。

## 6.5 引用・リポスト・リアクション

### 引用（kind 1）

- `content` は本文の後ろに空行と `nostr:note1…` を足したものです。
- `["q", <ID>, "", <作者>]` と `["p", <作者>]` を付けます。
- パブリックチャットのメッセージも、リポストではなく引用にします。

### リポスト（kind 6・16）

- 元の投稿が kind 1 なら kind 6、それ以外は kind 16 で `["k", <元の kind>]` を付けます。
- 署名の前に、元の投稿を作者の書き込みリレーから取り直します（20 秒まで）。取れなければ送りません。
- `["e", <ID>, <元の投稿を受け取ったリレー>]` と `["p", <作者>]` を付けます。リレーは、取り直したときに元の投稿が届いたリレーです。分からなければ読み込みリレーの先頭です。
- `content` は、取り直した署名つきの元の投稿の JSON です（NIP-18）。元の投稿に NIP-70 の `["-"]` があるときは空にします。保護された投稿を中に入れたリポストは、リレーに拒否されるためです。JSON の `/` は `\/` と書かずに `/` のまま書きます。

### リアクション（kind 7）

- `content` は `+`、Unicode の絵文字、またはカスタム絵文字の `:名前:` です。カスタム絵文字のときは `["emoji", <名前>, <URL>]` を付けます。
- 絵文字の後ろに隠しメッセージ（9.1）を付けることもできます。`content` は絵文字の直後に異体字セレクタが続く形で、`+` に付けるときは `❤️` にします。カスタム絵文字の `emoji` タグはそのまま付けます。
- `["e", <ID>, "", <作者>]`、`["p", <作者>]`、`["k", <対象の kind>]` を付けます。
- 消える投稿の設定はリアクションには使いません。
- 同じ投稿へ同じリアクションを二重に送らないよう、投稿とリアクションの中身ごとに下書きを分けて覚えています。

### 取り消し

リアクション・リポストの取り消しは kind 5 です。`["e", <リアクション・リポストの ID>]` と `["k", "7"]`（リポストなら `"6"`・`"16"`）を付け、`content` は「リアクションを取り消しました」「リポストを取り消しました」です。書き込みリレーへ送ります。署名した取り消しは受理されるまで端末に覚えておき、再送では同じものを送ります。

## 6.6 削除の依頼（kind 5、NIP-09）

自分の投稿の削除は次のとおりです。

- `["e", <ID>]`、アドレスで指すイベントなら `["a", <アドレス>]`、`["k", <kind>]`。`content` は空です。
- 送り先は次を合わせたものです。
  - 書き込みリレー
  - その投稿の相手（引用した相手、なければ自分以外の最初の `p`）の読み込みリレー 3 件まで（6.1 のゆるアウトボックスと同じ相手）
  - この起動中にその投稿を受理したリレー
- 受理されたら、その投稿を端末の一覧とキャッシュから外します。

リレーが削除のあとも投稿を返し続けるときは、「削除を再送」で、前に署名した依頼をそのまま送り直します。このときは上の送り先に、読み込みリレーとグローバルのリレーも足します。前の依頼が手元になければ、新しく署名します。

### ブロードキャスト

投稿の「…」の「ブロードキャスト（書き込みリレーへ送る）」で、署名済みの投稿をそのまま自分の書き込みリレーへ送ります。署名し直さないので、ほかの人の投稿も送れます。手元に署名の確かめられた版がなければ、作者の書き込みリレー（なければ読み込みリレー）から ID で読み直してから送ります。次のものは送りません。

- ほかの人の保護された投稿（NIP-70 の `["-"]` タグ）。本人以外が送ってはいけない決まりのため。
- 期限の切れた投稿（NIP-40）。
- 作者が削除を依頼した投稿。

## 6.7 プロフィール（kind 0）

1. 読み込みリレーから自分の kind 0 を取り直し、いちばん新しいものを前の版にします。
2. 前の版の `content` の JSON を読み、画面で変えた項目だけを書き換えます。このアプリが知らない項目は残します。前の版のタグもそのまま残します。
3. 画像・バナー・ウェブサイトは `https://` だけを受け付けます。`nip05` と `lud16` は形を確かめてから書きます。`bot` は真偽値、`birthday` は NIP-24 の形（年・月・日はどれも省略できる）で書きます。
4. 書き込みリレーへ送ります。

## 6.8 DM

### NIP-17（kind 14・15）

1. 相手の kind 10050 を、**自分の読み込みリレー**から探します。`relay` タグの `wss://` のものを 3 件まで使います。見つからなければ送らず、NIP-04 なら送れる場合があると知らせます。
2. rumor を作ります。kind 14 は `content` が本文、`["p", <相手>]` だけです。
3. seal（kind 13）は、rumor を NIP-44 で暗号化し、自分の鍵で署名します。`created_at` は 0〜2 日前のどこかにします。タグは付けません。
4. gift wrap（kind 1059）は、その場で作った使い捨ての鍵で seal を NIP-44 で暗号化して署名します。`["p", <受け取る人>]` を付け、`created_at` は 0〜2 日前のどこかにします。使い捨ての鍵は署名のあとすぐに消します。
5. 相手宛ての gift wrap は相手の kind 10050 のリレーへ、自分宛ての控えの gift wrap は自分の kind 10050 のリレー（公開していなければ書き込みリレー）へ送ります。

ファイル（kind 15）は、ファイルを AES-256-GCM で暗号化して Blossom にアップロードし、rumor の `content` をその URL にします。タグは `p`、`file-type`、`encryption-algorithm`（`aes-gcm`）、`decryption-key`、`decryption-nonce`、`x`（暗号化したものの SHA-256）、`ox`（元のファイルの SHA-256）、`size` です。

DM 受信リレー（kind 10050）は `["relay", <URL>]` を 3 件まで書き、書き込みリレーへ送ります。公開する前に、今公開されているものを読みます。読めなかったときは上書きを防ぐため公開しません。

### NIP-04（kind 4）

会話の画面で「旧方式 NIP-04」を選んだときに使います（送受信の相手と時刻が公開されることを画面に出します）。ファイルは送れません。`content` は NIP-04 で暗号化した本文、タグは `["p", <相手>]` です。書き込みリレーへ送ります。

## 6.9 パブリックチャット（NIP-28）

- メッセージ（kind 42）は `["e", <チャンネル>, <チャンネルのリレーの先頭>, "root"]` を付けます。返信なら `["e", <返信先>, <同じリレー>, "reply"]` と `["p", <返信先の作者>, <同じリレー>]` も付けます。送り先は、チャンネルの `relays` と自分の書き込みリレーの先頭 2 件（合わせて 8 件まで）です。
- チャンネルの作成（kind 40）の `content` は `name`・`about`・`relays`・`picture` の JSON です。`relays` は作るときに選んだリレー（最初は書き込みリレーの先頭 3 件）で、送り先も同じです。
- 参加中のチャンネル（kind 10005）は `["e", <チャンネル>, <チャンネルのリレーの先頭>]` を並べます。
- チャンネルの情報の更新（kind 41）は作りません。

## 6.10 下書き（NIP-37）

投稿欄と記事の下書きは、リレーに保存できます。

- kind 31234 で、`["d", <識別子>]`、`["k", <下書きの kind>]`、`["expiration", <90 日後>]` を付けます。
- `content` は、下書きのイベント（`kind`・`content`・`tags`・`created_at`・`pubkey`）の JSON を、自分宛てに NIP-44 で暗号化したものです。
- 記事の下書きの識別子は `article:<記事の d>` です。同じ記事を保存し直すと、前の下書きを置き換えます。
- 送り先は、kind 10013 に書かれた非公開のリレーです。kind 10013 は書き込みリレーから読み、自分宛ての NIP-44 で復号します。読めなければ書き込みリレーへ送ります。kind 10013 はこのアプリでは作りません。
- 下書きの削除は、同じ `d` と `k` で `content` を空にした版を送ります（`expiration` は付けません）。リレーの下書きから開いた投稿が受理されたときも、この方法で消します。

## 6.11 そのほか

### 記事（kind 30023、NIP-23）

- タグは `d`、`title`（300 文字まで）、`summary`（600 文字まで）、`image`（`https://` のみ）、`published_at`、`t`（20 個まで）です。`content` は Markdown の本文で、200,000 文字までです。
- 新しい記事の `d` は `penyotter-<UNIX 時刻>` です。
- 書き直したときは、`published_at` に最初に公開したときの時刻を残します。

### 投票（kind 1018、NIP-88）

`["e", <投票>]` と、選んだ選択肢の数だけ `["response", <選択肢の ID>]` を付けます。

### zap リクエスト（kind 9734、NIP-57）

- 相手のプロフィールの `lud16` から LNURL を調べ、`allowsNostr` と `nostrPubkey` があり、金額が範囲内のときだけ作ります。
- タグは `["relays", <書き込みリレー 10 件まで>...]`、`amount`（ミリサトシ）、`lnurl`、`p`、`e`、`k` です。`content` はコメント（500 文字まで）です。
- リレーには送らず、LNURL のコールバックの `nostr` パラメータとして渡します。返ってきた請求書は `lightning:` の URI で端末のウォレットに渡します。

### 通報（kind 1984、NIP-56）

投稿の通報は `["e", <ID>, <種類>]` と `["p", <作者>]`、人の通報は `["p", <公開鍵>, <種類>]` です。種類は `nudity`・`malware`・`profanity`・`illegal`・`spam`・`impersonation`・`other`。`content` は理由（1,000 文字まで）です。

### ステータス（kind 30315、NIP-38）・Blossom のサーバー一覧（kind 10063）

ステータスは前の版を読み直してから書き換えます。Blossom のサーバー一覧は `["server", <https の URL>]` を 12 件まで並べます。

## 6.12 消去の依頼（kind 62、NIP-62）

アカウントの投稿をすべて消すよう、リレーに頼むものです。取り消せません。

- 特定のリレーにだけ頼むときは `["relay", <URL>]` を並べ、そのリレーへ送ります。
- すべてのリレーに頼むときは `["relay", "ALL_RELAYS"]` を付け、知っているリレー（設定のすべてのリレー、検索リレー、最初の設定の 3 件）へ送ります。
- `content` は理由（1,000 文字まで）です。
- 画面で「消去」と入力するまで送れません。

実際に送って確かめたことはありません（未確認）。

# 2. 全体の構成

対象の版: 0.186.0

## 2.1 アプリの形

- Android（8.0 / API 28 以上）向けのネイティブアプリです。Kotlin と Jetpack Compose（Material 3）で作っています。
- 画面は 1 つの Activity の中で切り替えます。下のタブは「ホーム・通知・検索・チャット・その他」で、左右のスワイプでも移れます（端でループします）。
- 使う権限は `INTERNET` と `ACCESS_NETWORK_STATE` だけです。暗号化されていない HTTP（`http://`、`ws://`）では通信しません。
- サーバーはありません。アプリはリレーと、画像・リンク先などのサーバーに直接つなぎます（10 章）。
- アプリを開いている間だけ通信します。裏で動き続けるサービスやプッシュ通知はありません。裏に回ると通知の購読を止め、戻ると続きから読み直します（5.3）。

## 2.2 中の分け方

コードは 3 つの層に分けています。

| 層 | 役割 |
|---|---|
| data | リレーとの WebSocket、イベントの符号化と署名の確かめ、暗号（NIP-04・NIP-44・ncryptsec）、署名アプリ・リモート署名とのやり取り、端末への保存、HTTP（画像のアップロード、NIP-05、NIP-11、LNURL など） |
| domain | Nostr のイベントの解釈と組み立て。タグの読み方、スレッドのたどり方、リポスト・引用・削除・期限の扱い、一覧の書き換えの安全策など。Android に依存しないので、JVM の単体テストで確かめる |
| ui | 画面と、画面ごとの状態の管理。どの REQ をどのリレーへ送るかは、主にこの層の各画面の管理役が決める |

イベントの組み立て（6 章）と解釈（8 章）は domain にまとめ、画面からは同じ関数を使います。たとえばホーム・プロフィール・リストのリポスト元の探し方（5.2）は同じものです。

アカウントを切り替えると、そのアカウント用の読み込みをすべてやり直します。前のアカウントの取得の結果が、後から届いても混ざらないようにしています。

## 2.3 端末に保存するもの

保存先はすべてアプリの専用領域です。ほかのアプリからは読めません。Android の自動バックアップ（クラウドへのバックアップと機種変更時の引き継ぎ）からは全部外しています。秘密鍵がバックアップ経由で端末の外に出ないようにするためです。

| 何を | 内容 | 量 |
|---|---|---|
| 秘密鍵 | 端末の Android Keystore の鍵で AES-GCM で暗号化して保存。Keystore の鍵は端末の外に出せない | アカウントごと |
| リモート署名のクライアント鍵 | 秘密鍵と同じ方法で暗号化 | アカウントごと |
| アカウントの設定 | リレー、表示の設定など | アカウントごと |
| タイムラインのキャッシュ | ホーム（フォロー中・グローバル）と、スレッドなどで見た投稿。最後に見ていた位置 | 一覧ごとに既定 2,000 件（500〜5,000 件で変えられる） |
| プロフィールのキャッシュ | kind 0 の名前・画像・カスタム絵文字など | 古いものは新しいもので置き換える |
| 通知 | 受け取った通知と既読の印 | 500 件 |
| 下書き | 投稿欄の下書き、署名済みで送信待ちのイベント、送信結果 | 投稿欄ごと |
| 一覧の履歴 | フォロー・ミュートなど一覧の、変更前と署名後の版（7 章） | 一覧ごとに 100 版・2MB まで（固定した 20 版は別） |
| 相手のリレーリスト | kind 10002 の読み込み・書き込みリレー（4.4.1） | 見つかったら 6 時間、なければ 10 分 |
| 削除が依頼された投稿の ID | 8.1 | アカウントごとに 2,000 件 |
| 画像のキャッシュ | 表示した画像 | 既定 64MB（16〜256MB で変えられる） |

- タイムラインのキャッシュ・プロフィール・通知は、アカウントごとに別のデータベースにしています。
- データベースが壊れていたら、そのアカウントのキャッシュを作り直します。キャッシュはリレーから取り直せるものだけです。
- アカウントを端末から外すと、そのアカウントの鍵（Keystore の鍵を先に消す）・設定・キャッシュを消します。
- 端末の外に出す暗号化バックアップは、まだありません（設計中）。

## 2.4 端末内の検索

検索画面では、リレーに問い合わせる前に、端末のキャッシュ（ホームの 2 つの一覧、スレッドで見た投稿、プロフィールの新しい 2,000 件）から探して先に出します（5.6）。メンションの補完（9 章）も同じプロフィールから探します。
